# agent-clicker — Обзор сервиса для клиента

## Что делает сервис

**agent-clicker** — это автоматизированный сервис, который эмулирует поведение реальных пользователей на сайтах. Каждый запуск выглядит как отдельный живой человек: уникальное устройство, браузер, IP-адрес и манера работы с сайтом.

---

## Стек технологий

### Язык и выполнение
| Технология | Роль |
|---|---|
| **Python 3.11+** | Основной язык сервиса |
| **asyncio** | Параллельное выполнение нескольких задач одновременно без блокировок |

### Браузерная автоматизация
| Технология | Роль |
|---|---|
| **Playwright** | Управляет браузером (Chromium, Firefox, WebKit): открывает страницы, кликает, заполняет формы, скроллит |
| **playwright-stealth + собственные скрипты** | Скрывают признаки автоматизации — браузер выглядит как обычный пользовательский |
| **human_behavior (собственный модуль)** | Имитирует человеческое поведение: плавные траектории мыши, нерегулярные паузы, опечатки при вводе, неравномерный скролл |

### База данных
| Технология | Роль |
|---|---|
| **PostgreSQL 15+** | Хранит все задачи и их статусы |
| **asyncpg** | Быстрый асинхронный драйвер для работы с PostgreSQL |
| **Alembic** | Управляет изменениями структуры базы данных (миграции) |

### Прокси и сеть
| Технология | Роль |
|---|---|
| **Резидентные / мобильные прокси** | Каждая задача выполняется с уникального реального IP-адреса |

### Очередь задач
| Технология | Роль |
|---|---|
| **PostgreSQL (SELECT FOR UPDATE SKIP LOCKED)** | Встроенная очередь задач — каждый воркер берёт задачу без конфликтов с другими воркерами |

### Планировщик действий
| Технология | Роль |
|---|---|
| **LLM (OpenAI-совместимый API)** | По текстовому описанию задачи автоматически составляет план действий на сайте |
| **Pydantic** | Проверяет корректность плана перед запуском |

### Конфигурация и качество
| Технология | Роль |
|---|---|
| **pydantic-settings** | Типизированная конфигурация из `.env`-файла |
| **structlog** | Структурированное логирование всех событий |
| **ruff** | Линтер и форматтер кода |
| **mypy** | Статическая проверка типов |
| **pytest + pytest-asyncio** | Автотесты |

### Инфраструктура
| Технология | Роль |
|---|---|
| **Docker + docker-compose** | Контейнеризация: сервис и база данных запускаются одной командой |

## Жизненный цикл задачи

```
Клиент создаёт задачу (URL + описание действий)
         │
         ▼
  Очередь задач (PostgreSQL)
         │
         ▼
  Диспетчер выбирает задачу и назначает воркера
         │
         ▼
  Воркер генерирует уникальный профиль устройства
  (браузер, экран, язык, часовой пояс, IP)
         │
         ▼
  LLM составляет план действий на сайте
         │
         ▼
  Playwright открывает сайт и выполняет план
  (с имитацией человеческого поведения)
         │
         ▼
  Задача завершена → статус: done / failed
```

## Имитация реального пользователя

| Аспект | Что делает сервис |
|---|---|
| **Движение мыши** | Плавные изогнутые траектории (кривые Безье), лёгкий промах и доводка до цели |
| **Клики** | Пауза перед кликом 80–400 мс, иногда повторное наведение |
| **Ввод текста** | Покнопочный набор (~120 мс/символ), редкие опечатки с исправлением |
| **Скролл** | Короткими «толчками», иногда небольшой откат назад |
| **Паузы** | Случайные задержки между действиями 1–15 с |
| **Время на сайте** | Минимум 30 с, в среднем 1–3 минуты, включая просмотр страниц |
| **Уникальность** | Каждая задача — новый браузерный профиль, новый IP, новые fingerprints |

---

## Отказоустойчивость

- Задачи повторяются автоматически при сбое (до 3 попыток с нарастающим интервалом).
- Зависшие задачи обнаруживаются и перезапускаются watchdog-процессом.
- При ошибке сохраняются скриншоты и HAR-файлы для диагностики.
